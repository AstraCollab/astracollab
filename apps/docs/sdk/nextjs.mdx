## Next.js SDK

The AstraCollab Next.js SDK provides React hooks, components, and utilities for building file upload and management features in Next.js applications.

## Installation

```bash
npm install @astracollab/nextjs
```

<Note>
  This package automatically installs `@tanstack/react-query` and `axios` as dependencies, so you don't need to install them separately.
</Note>

## Quick Start

### Basic File Upload Component

```tsx
import { FileUploaderWithUI } from '@astracollab/nextjs';

function MyComponent() {
  const config = {
    baseURL: 'https://api.astracollab.app',
    apiKey: process.env.ASTRACOLLAB_API_KEY
  };

  return (
    <FileUploaderWithUI
      config={config}
      folderId="my-folder"
      orgId="my-org"
      maxFiles={5}
      onUploadComplete={(results) => {
        console.log('Upload completed:', results);
      }}
      onUploadError={(error, fileId) => {
        console.error('Upload failed:', error);
      }}
    />
  );
}
```

### Custom UI with Hooks

```tsx
import { useUploadService, useUpload } from '@astracollab/nextjs';

function CustomUploader() {
  const config = {
    baseURL: 'https://api.astracollab.app',
    apiKey: process.env.ASTRACOLLAB_API_KEY
  };

  const uploadService = useUploadService(config);
  const { uploadFiles, uploadProgress, isUploading } = useUpload(uploadService);

  const handleFileSelect = (event) => {
    const files = Array.from(event.target.files);
    uploadFiles(files);
  };

  return (
    <div>
      <input type="file" multiple onChange={handleFileSelect} />
      {isUploading && <p>Uploading files...</p>}
      
      {/* Display progress for each file */}
      {Array.from(uploadProgress.entries()).map(([fileId, progress]) => (
        <div key={fileId}>
          <p>{progress.fileName}: {progress.progressPercentage}%</p>
        </div>
      ))}
    </div>
  );
}
```

## Hooks

### useUploadService

Creates and manages an upload service instance.

```tsx
const uploadService = useUploadService({
  baseURL: string
  apiKey?: string
  timeout?: number
});
```

### useUpload

Provides upload functionality with progress tracking.

```tsx
const {
  uploadFiles,
  uploadProgress,
  isUploading,
  cancelUpload,
  clearProgress
} = useUpload(uploadService);
```

<Note>
  `cancelUpload(fileId)` aborts an in-flight upload and marks its progress
  entry as `canceled`. Canceled files do not count against storage — the
  service cleans up the reserved record. `clearProgress()` resets the whole
  progress map, e.g. after a completed batch.
</Note>

### useFiles

Fetches files from the API.

```tsx
const {
  files,
  isLoading,
  error,
  refetch
} = useFiles(baseURL, apiKey, folderId, orgId);
```

**Parameters:**
- `baseURL` (string, required): API base URL
- `apiKey` (string, optional): API key — required for private workspaces, omit for authenticated browser calls
- `folderId` (string, optional): Only list files inside this folder
- `orgId` (string, optional): Scope the listing to an organization

Backed by React Query: results are cached under `["files", folderId, orgId]`,
and `refetch()` re-requests the list after uploads or deletes.

### Tuning batch uploads

`uploadFiles` batches through the upload service. Tune concurrency and
chunking when you have many files, large files, or flaky networks:

| Option | Default behavior | When to change it |
| --- | --- | --- |
| `chunkSize` | Service default (~5 MB chunks) | Lower it on unstable connections so a failed chunk costs less; raise it to cut request overhead on fast links |
| `maxConcurrentFiles` | Small default parallelism | Raise for bulk ingest of many small files; lower on mobile or metered connections |
| `maxConcurrentChunks` | Small default parallelism | Raise when uploading a few very large files to saturate bandwidth |
| `retryAttempts` | Limited retries per chunk | Raise for background/overnight transfers where you prefer retries over surfacing errors |

```tsx
const uploadService = useUploadService({
  baseURL: 'https://api.astracollab.app',
  apiKey: process.env.NEXT_PUBLIC_ASTRACOLLAB_API_KEY,
});

// Example: large-media ingest profile
await uploadService.uploadMultipleFiles({
  files: filesToUpload,
  folderId: 'ingest-2026',
  chunkSize: 10 * 1024 * 1024, // 10 MB chunks
  maxConcurrentFiles: 2,
  maxConcurrentChunks: 4,
  retryAttempts: 5,
  onProgress: (map) => setProgress(new Map(map)),
  onSuccess: (results) => console.log(`Uploaded ${results.length} files`),
  onError: (msg, fileId) => console.error(fileId, msg),
});
```

### FileUploadProgress

```tsx
interface FileUploadProgress {
  fileId: string;
  fileName: string;
  totalBytes: number;
  uploadedBytes: number;
  progressPercentage: number;
  status: 'pending' | 'uploading' | 'completed' | 'failed' | 'canceled';
  error?: string;
}
```

The `status` field is the source of truth for UI state: `pending` (queued,
not started), `uploading` (bytes in flight), `completed`, `failed` (see
`error`), or `canceled` (user-aborted).

### File Listing

```tsx
function FileList() {
  const { files, isLoading, error } = useFiles(
    'https://api.astracollab.app',
    process.env.ASTRACOLLAB_API_KEY,
    'my-folder',
    'my-org'
  );

  if (isLoading) return <div>Loading files...</div>;
  if (error) return <div>Error: {error.message}</div>;

  return (
    <ul>
      {files.map((file) => (
        <li key={file.id}>{file.name}</li>
      ))}
    </ul>
  );
}
```

## Advanced Usage

### Direct Service Usage

```tsx
import { UploadService } from '@astracollab/nextjs';

const uploadService = new UploadService('https://api.astracollab.app', 'your-api-key');

// Upload a single file
const fileId = await uploadService.uploadSingleFile({
  file: fileObject,
  fileName: 'example.jpg',
  folderId: 'my-folder',
  orgId: 'my-org'
});

// Upload multiple files
await uploadService.uploadMultipleFiles({
  files: [
    { id: '1', file: file1, name: 'file1.jpg', size: 1024 },
    { id: '2', file: file2, name: 'file2.jpg', size: 2048 }
  ],
  folderId: 'my-folder',
  orgId: 'my-org',
  onProgress: (progressMap) => {
    console.log('Upload progress:', progressMap);
  },
  onError: (errorMsg, fileId) => {
    console.error('Upload error:', errorMsg);
  },
  onSuccess: (results) => {
    console.log('Upload success:', results);
  }
});
```

## Error Handling

The SDK provides comprehensive error handling:

```tsx
function UploadWithErrorHandling() {
  const { uploadFiles, uploadProgress } = useUpload(uploadService);

  const handleUpload = async (files) => {
    try {
      await uploadFiles(files);
    } catch (error) {
      console.error('Upload failed:', error);
      // Handle error appropriately
    }
  };

  return (
    <FileUploaderWithUI
      config={config}
      onUploadError={(error, fileId) => {
        console.error(`Upload failed for ${fileId}:`, error);
        // Show user-friendly error message
      }}
    />
  );
}
```

## Best Practices

**Keep the key in environment variables, keyed to the runtime.** Server-side
code reads `ASTRACOLLAB_API_KEY`; browser-exposed code gets a separate,
differently-named key (`NEXT_PUBLIC_ASTRACOLLAB_API_KEY`) so the two can be
rotated and revoked independently. Never reuse the server key in client
components — anything with the `NEXT_PUBLIC_` prefix ships in the bundle.

**Treat upload errors as product surface, not console noise.** Branch on
`AstraCollabError`'s `status` and `code`: `4xx` tells the user something
actionable (file too large, wrong type), `5xx` and network errors are retry
candidates. An upload that fails silently is the bug report you'll get at 9pm.

**Show progress as a first-class UI element.** The `uploadProgress` map gives
you per-file bytes, percentage, and status (`uploading`, `failed`,
`canceled`…). Files above a few megabytes without visible progress read as
"frozen" — and users close the tab, which guarantees a failed upload.

**Validate before you upload, not while.** Check size against plan limits and
type against your allowlist at file-select time. It's cheaper for the user,
and it keeps your error surface down to genuine network/server issues. This
is UX on the client — repeat the checks server-side, where it's security.

**Work with the rate limiter, not against it.** Keep 2–4 uploads in flight,
back off on `429` using `X-RateLimit-Reset`, and tune the batch options
(`maxConcurrentFiles`, `maxConcurrentChunks`, `retryAttempts`) for your
network profile rather than maxing them out. Bulk ingest jobs should be the
polite one in the room.
