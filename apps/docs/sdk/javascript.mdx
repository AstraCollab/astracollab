## JavaScript SDK

The AstraCollab JavaScript SDK provides a pure JavaScript client for Node.js and browser environments. Perfect for server-side applications, CLI tools, and browser-based file management.

## Installation

```bash
npm install @astracollab/js
```

## Quick Start

### Basic Usage

```javascript
import { AstraCollabClient } from '@astracollab/js';

const client = new AstraCollabClient({
  apiKey: 'your-api-key-here'
});

// List files
const files = await client.listFiles();
console.log('Files:', files);

// Upload a file
const fileId = await client.uploadFile({
  file: fileObject,
  fileName: 'example.jpg',
  folderId: 'optional-folder-id'
});
console.log('File uploaded:', fileId);
```

### Node.js Example

```javascript
import { AstraCollabClient } from '@astracollab/js';
import fs from 'fs';

const client = new AstraCollabClient({
  apiKey: process.env.ASTRACOLLAB_API_KEY
});

// Upload a file from the filesystem
const fileBuffer = fs.readFileSync('./example.jpg');
const file = new Blob([fileBuffer], { type: 'image/jpeg' });

const fileId = await client.uploadFile({
  file,
  fileName: 'example.jpg',
  folderId: 'my-folder'
});

console.log('File uploaded with ID:', fileId);
```

## API Reference

### Constructor

```javascript
const client = new AstraCollabClient(config);
```

**Parameters:**
- `config.apiKey` (string, required): Your AstraCollab API key
- `config.baseURL` (string, optional): API base URL (defaults to `https://api.astracollab.app`). For staging integrations use `https://staging.astracollab.app`
- `config.timeout` (number, optional): Request timeout in milliseconds. Requests that exceed it reject with an `AstraCollabError`

All methods reject with an [`AstraCollabError`](#error-handling) on failure, which carries the HTTP `status`, a machine-readable `code`, and optional `details`.

### File Management

#### List Files

```javascript
const files = await client.listFiles(folderId);
```

**Parameters:**
- `folderId` (string, optional): Folder ID to list files from

**Returns:** Array of file objects

#### Upload File

```javascript
const fileId = await client.uploadFile(options);
```

**Parameters:**
- `options.file` (File|Blob, required): File to upload
- `options.fileName` (string, optional): Custom file name
- `options.folderId` (string, optional): Folder to upload to
- `options.orgId` (string, optional): Organization ID
- `options.onProgress` (function, optional): Progress callback

**Returns:** File ID string

#### Download File

```javascript
const fileBuffer = await client.downloadFile(fileId);
```

**Parameters:**
- `fileId` (string, required): ID of the file to download

**Returns:** Buffer containing file data

#### Get File Details

```javascript
const file = await client.getFile(fileId);
```

**Parameters:**
- `fileId` (string, required): ID of the file

**Returns:** File object with metadata

#### Delete File

```javascript
await client.deleteFile(fileId);
```

**Parameters:**
- `fileId` (string, required): ID of the file to delete

### Folder Management

#### List Folders

```javascript
const folders = await client.listFolders(parentFolderId);
```

**Parameters:**
- `parentFolderId` (string, optional): Parent folder ID

**Returns:** Array of folder objects

#### Create Folder

```javascript
const folder = await client.createFolder(name, parentFolderId);
```

**Parameters:**
- `name` (string, required): Folder name
- `parentFolderId` (string, optional): Parent folder ID

**Returns:** Created folder object

### API Key Management

#### List API Keys

```javascript
const keys = await client.listApiKeys();
```

**Returns:** Array of API key objects

#### Create API Key

```javascript
const key = await client.createApiKey(name);
```

**Parameters:**
- `name` (string, required): API key name

**Returns:** Created API key object

#### Revoke API Key

```javascript
await client.revokeApiKey(keyId);
```

**Parameters:**
- `keyId` (string, required): API key ID to revoke

### Multipart Upload

For large files, use the multipart flow: reserve the file, upload chunks to
presigned URLs in any order, then commit. Use this when uploads exceed ~100 MB
or when you want per-chunk retry behavior on unreliable networks.

#### Start a multipart upload

```javascript
const start = await client.startMultipartUpload({
  fileName: 'conference-recording.mp4',
  fileType: 'video/mp4',
  fileSize: 4_712_889_344,
  totalChunks: 12,
  folderId: 'optional-folder-id',
});
```

**Parameters:**
- `fileName` (string, required): Original file name
- `fileType` (string, required): MIME type
- `fileSize` (number, required): Total size in bytes
- `totalChunks` (number, required): Number of chunks you will upload
- `folderId` (string, optional): Folder to place the file in

**Returns:** An object with `uploadId`, `fileId`, `key`, and `presignedUrls` —
an array of `{ url, partNumber }` upload targets, one per chunk.

#### Upload the chunks

Each entry in `presignedUrls` is a `PUT` target for exactly one chunk. Chunks
can be uploaded concurrently and in any order:

```javascript
const parts = await Promise.all(
  start.presignedUrls.map(async ({ url, partNumber }) => {
    const chunk = chunkSlice(fileBuffer, partNumber); // your chunking logic
    const res = await fetch(url, {
      method: 'PUT',
      body: chunk,
      headers: { 'Content-Type': 'application/octet-stream' },
    });
    return {
      partNumber,
      etag: res.headers.get('etag'),
    };
  }),
);
```

<Note>
  Presigned URLs are time-limited. If an upload is abandoned mid-way, the
  reserved file stays in `pending` state until it is completed or cleaned up.
  Keep the `partNumber → etag` mapping from every successful `PUT` — the
  complete call requires all of them.
</Note>

#### Complete the upload

```javascript
await client.completeMultipartUpload({
  uploadId: start.uploadId,
  key: start.key,
  fileId: start.fileId,
  parts,
});
```

**Parameters:**
- `uploadId` (string, required): From the start response
- `key` (string, required): Storage key from the start response
- `fileId` (string, required): File record ID from the start response
- `parts` (array, required): Every `{ partNumber, etag }` from the chunk uploads

Once completed, the file appears in `listFiles` like any other upload.

### Billing

#### Get billing info

```javascript
const billing = await client.getBillingInfo();
```

**Returns:** An object with the subscription summary and cost breakdown:

```javascript
{
  subscription: {
    plan: 'creator',
    status: 'active',
    includedStorageGB: 500,
    additionalStorageGB: 0,
    currentUsageGB: 231.4,
    overageGB: 0,
    filesCount: 1849,
    monthlyCost: { base: 1200, overage: 0, total: 1200 }
  }
}
```

Monetary values are in cents. `overageGB` is the amount of storage beyond
`includedStorageGB + additionalStorageGB` in the current period.

#### Get usage history

```javascript
const history = await client.getUsageHistory();
```

**Returns:** An array of per-period usage records:

```javascript
[
  { period: '2026-09', filesCount: 1620, storageGB: 201.8 },
  { period: '2026-10', filesCount: 1849, storageGB: 231.4 }
]
```

Use this to render usage graphs or to alert before an overage begins.

## Examples

### Upload Multiple Files

```javascript
import { AstraCollabClient } from '@astracollab/js';

const client = new AstraCollabClient({
  apiKey: 'your-api-key-here'
});

const files = [
  { name: 'file1.jpg', data: file1Blob },
  { name: 'file2.pdf', data: file2Blob },
  { name: 'file3.txt', data: file3Blob }
];

for (const file of files) {
  try {
    const fileId = await client.uploadFile({
      file: file.data,
      fileName: file.name,
      folderId: 'my-folder'
    });
    console.log(`Uploaded ${file.name} with ID: ${fileId}`);
  } catch (error) {
    console.error(`Failed to upload ${file.name}:`, error);
  }
}
```

### Progress Tracking

```javascript
const fileId = await client.uploadFile({
  file: fileBlob,
  fileName: 'large-file.zip',
  onProgress: (progress) => {
    console.log(`Upload progress: ${progress}%`);
  }
});
```

### Error Handling

```javascript
try {
  const files = await client.listFiles();
  console.log('Files:', files);
} catch (error) {
  if (error.response?.status === 401) {
    console.error('Authentication failed. Check your API key.');
  } else if (error.response?.status === 429) {
    console.error('Rate limit exceeded. Try again later.');
  } else {
    console.error('An error occurred:', error.message);
  }
}
```

### CLI Tool Example

```javascript
#!/usr/bin/env node
import { AstraCollabClient } from '@astracollab/js';
import fs from 'fs';

const client = new AstraCollabClient({
  apiKey: process.env.ASTRACOLLAB_API_KEY
});

async function uploadFile(filePath) {
  try {
    const fileBuffer = fs.readFileSync(filePath);
    const fileName = filePath.split('/').pop();
    const file = new Blob([fileBuffer]);

    const fileId = await client.uploadFile({
      file,
      fileName
    });

    console.log(`✅ File uploaded successfully!`);
    console.log(`📁 File ID: ${fileId}`);
    console.log(`🔗 View at: https://app.astracollab.app/files/${fileId}`);
  } catch (error) {
    console.error('❌ Upload failed:', error.message);
    process.exit(1);
  }
}

// Usage: node upload.js path/to/file.jpg
const filePath = process.argv[2];
if (!filePath) {
  console.error('Please provide a file path');
  process.exit(1);
}

uploadFile(filePath);
```

### Browser Example

```html
<!DOCTYPE html>
<html>
<head>
    <title>AstraCollab File Upload</title>
</head>
<body>
    <input type="file" id="fileInput" multiple>
    <button onclick="uploadFiles()">Upload Files</button>
    <div id="progress"></div>

    <script type="module">
        import { AstraCollabClient } from 'https://unpkg.com/@astracollab/js@latest/dist/index.mjs';

        const client = new AstraCollabClient({
            apiKey: 'your-api-key-here'
        });

        window.uploadFiles = async function() {
            const fileInput = document.getElementById('fileInput');
            const progressDiv = document.getElementById('progress');
            
            const files = Array.from(fileInput.files);
            
            for (const file of files) {
                try {
                    const fileId = await client.uploadFile({
                        file,
                        fileName: file.name,
                        onProgress: (progress) => {
                            progressDiv.innerHTML = `Uploading ${file.name}: ${progress}%`;
                        }
                    });
                    
                    progressDiv.innerHTML += `<br>✅ ${file.name} uploaded (ID: ${fileId})`;
                } catch (error) {
                    progressDiv.innerHTML += `<br>❌ Failed to upload ${file.name}: ${error.message}`;
                }
            }
        };
    </script>
</body>
</html>
```

## Error Handling

The SDK throws errors for various scenarios:

```javascript
try {
  const files = await client.listFiles();
} catch (error) {
  switch (error.response?.status) {
    case 401:
      console.error('Invalid API key');
      break;
    case 403:
      console.error('Insufficient permissions');
      break;
    case 404:
      console.error('Resource not found');
      break;
    case 429:
      console.error('Rate limit exceeded');
      break;
    default:
      console.error('An error occurred:', error.message);
  }
}
```

## Best Practices

**Store keys in environment variables, never in source.** The client reads
`config.apiKey` from wherever you construct it — make that
`process.env.ASTRACOLLAB_API_KEY` on the server. A key that lands in a git
history is a key you should rotate, so don't commit one in the first place:
add the `.env` file to `.gitignore` before the first commit. If a key does
leak, [revoke it](#revoke-api-key) immediately and rotate — that's minutes of
work versus an incident.

**Handle `AstraCollabError` at one boundary.** Every client method rejects
with the same error shape (`status`, `code`, `details`), so wrap calls once —
a helper or middleware — and branch on the code: `4xx` is actionable and
shouldn't be retried; `5xx` and network errors are retry candidates with
exponential backoff and jitter. This single catch site is what keeps error
handling from sprawling across every call site.

**Use progress callbacks for anything large.** `onProgress` turns a
multi-minute upload into an honest progress bar. Better: switch to the
[multipart flow](#multipart-upload) for large files, where failed chunks
retry individually instead of restarting the whole upload.

**Be a good API citizen under load.** Batch scripts and cron jobs are the
usual rate-limit offenders. Keep concurrency bounded (2–4 parallel uploads),
honor `429` responses by waiting for `X-RateLimit-Reset`, and back off with
jitter rather than hammering on a fixed interval. A nightly ingest that
respects the limiter finishes faster than one that spends the night retrying.

**Validate files before they leave your process.** Check size and MIME type
against your plan limits and allowlist before calling `uploadFile` — you'll
reject bad input in milliseconds instead of after the upload. This is
correctness for your users and hygiene for the workspace; the API will still
enforce its own limits, just less helpfully.
