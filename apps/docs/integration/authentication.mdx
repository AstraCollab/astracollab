## Authentication

Integrate AstraCollab authentication into your applications using API keys, OAuth, or custom authentication flows.

## API Key Authentication

### Basic Integration

The simplest way to authenticate is with an API key on one of the official
SDKs. Keys are workspace-scoped: they can only see and act on the workspace
that issued them.

```javascript
import { AstraCollabClient } from '@astracollab/js';

// Initialize client with API key
const client = new AstraCollabClient({
  apiKey: process.env.ASTRACOLLAB_API_KEY,
});

// Make authenticated requests
const files = await client.listFiles();
```

For React applications, the Next.js SDK accepts the same configuration:

```tsx
import { FileUploaderWithUI } from '@astracollab/nextjs';

<FileUploaderWithUI
  config={{
    baseURL: 'https://api.astracollab.app',
    apiKey: process.env.NEXT_PUBLIC_ASTRACOLLAB_API_KEY,
  }}
  onUploadComplete={(results) => console.log(results)}
/>
```

<Note>
  Server-side keys (`ASTRACOLLAB_API_KEY`) and browser-exposed keys
  (`NEXT_PUBLIC_ASTRACOLLAB_API_KEY`) should be different keys with different
  names. Rotate them independently.
</Note>

### Environment-Based Configuration

Configure API keys for different environments. Staging has its own base URL
and dataset, so give each environment its own key **and** its own client
configuration:

```javascript
// config/auth.js
const configs = {
  production: {
    apiKey: process.env.ASTRACOLLAB_PROD_API_KEY,
    baseURL: 'https://api.astracollab.app',
  },
  staging: {
    apiKey: process.env.ASTRACOLLAB_STAGING_API_KEY,
    baseURL: 'https://staging.astracollab.app',
  },
  development: {
    apiKey: process.env.ASTRACOLLAB_DEV_API_KEY,
    baseURL: 'https://staging.astracollab.app',
  },
};

export const getClient = () => {
  const env = process.env.NODE_ENV === 'production' ? 'production' : 'development';
  const config = configs[env];
  if (!config?.apiKey) throw new Error(`No AstraCollab key configured for ${env}`);
  return new AstraCollabClient(config);
};
```

### Proxying from the Browser

API keys belong on the server. For browser apps, wrap calls in your own
backend so the key never ships to the client — a Next.js route handler makes
this a few lines:

```ts
// app/api/storage/files/route.ts
import { NextRequest, NextResponse } from 'next/server';
import { AstraCollabClient } from '@astracollab/js';

const client = new AstraCollabClient({
  apiKey: process.env.ASTRACOLLAB_API_KEY,
});

export async function GET() {
  try {
    const files = await client.listFiles();
    return NextResponse.json({ success: true, data: files });
  } catch (error) {
    return NextResponse.json(
      { success: false, error: { message: 'Upstream storage error' } },
      { status: 502 },
    );
  }
}
```

The client calls your route; your route calls AstraCollab. Your auth decides
who gets through the front door — the API key stays inside.

## Error Handling

### Authentication Errors

Handle authentication errors gracefully:

```javascript
class AuthErrorHandler {
  static handleError(error) {
    switch (error.code) {
      case 'INVALID_API_KEY':
        return this.handleInvalidKey();
      case 'API_KEY_EXPIRED':
        return this.handleExpiredKey();
      case 'INSUFFICIENT_PERMISSIONS':
        return this.handleInsufficientPermissions();
      case 'RATE_LIMITED':
        return this.handleRateLimit();
      default:
        return this.handleGenericError(error);
    }
  }

  static handleInvalidKey() {
    // Redirect to login or refresh token
    window.location.href = '/auth/login';
  }

  static handleExpiredKey() {
    // Attempt to refresh token
    return this.refreshToken();
  }

  static handleInsufficientPermissions() {
    // Show permission error
    return {
      type: 'error',
      message: 'You don\'t have permission to perform this action'
    };
  }

  static handleRateLimit() {
    // Show rate limit message
    return {
      type: 'warning',
      message: 'Rate limit exceeded. Please try again later.'
    };
  }

  static handleGenericError(error) {
    console.error('Authentication error:', error);
    return {
      type: 'error',
      message: 'An authentication error occurred'
    };
  }
}
```

## Security Best Practices

### Key Storage

Store API keys securely:

```javascript
// Secure key storage
const secureKeyStorage = {
  // Browser environment
  browser: {
    store: (key, value) => {
      // Use sessionStorage for temporary storage
      sessionStorage.setItem(key, value);
    },
    retrieve: (key) => {
      return sessionStorage.getItem(key);
    },
    remove: (key) => {
      sessionStorage.removeItem(key);
    }
  },

  // Node.js environment
  node: {
    store: (key, value) => {
      // Use environment variables or secure key management
      process.env[key] = value;
    },
    retrieve: (key) => {
      return process.env[key];
    },
    remove: (key) => {
      delete process.env[key];
    }
  }
};
```

### Token Validation

Validate tokens before use:

```javascript
const validateToken = (token) => {
  if (!token) {
    throw new Error('No token provided');
  }

  if (token.length < 20) {
    throw new Error('Invalid token format');
  }

  // Additional validation as needed
  return true;
};

const safeClientInit = (token) => {
  try {
    validateToken(token);
    return new AstraCollabClient({ apiKey: token });
  } catch (error) {
    console.error('Token validation failed:', error);
    throw error;
  }
};
```

## Testing Authentication

### Mock Authentication

Create mock authentication for testing:

```javascript
// test/mocks/auth.js
import { AstraCollabClient } from '@astracollab/js';
export const mockAuth = {
  apiKey: 'test_api_key_1234567890abcdef',
  user: {
    id: 'user_123',
    email: 'test@example.com',
    permissions: ['files:read', 'files:write']
  },
  
  createMockClient: () => {
    return new AstraCollabClient({ apiKey: mockAuth.apiKey });
  },
  
  mockLogin: async (email, password) => {
    if (email === 'test@example.com' && password === 'password') {
      return {
        success: true,
        user: mockAuth.user,
        apiKey: mockAuth.apiKey
      };
    }
    throw new Error('Invalid credentials');
  }
};
```

### Integration Tests

Test authentication integration:

```javascript
// test/integration/auth.test.js
import { AstraCollabClient } from '@astracollab/js';

describe('Authentication Integration', () => {
  test('should authenticate with valid API key', async () => {
    const client = new AstraCollabClient({ apiKey: process.env.TEST_API_KEY });
    const files = await client.listFiles();
    expect(files).toBeDefined();
  });

  test('should reject invalid API key', async () => {
    const client = new AstraCollabClient({ apiKey: 'invalid_key' });
    await expect(client.listFiles()).rejects.toThrow();
  });

  test('should handle expired token', async () => {
    const client = new AstraCollabClient({ apiKey: expiredToken });
    await expect(client.listFiles()).rejects.toThrow();
  });
});
```

## Best Practices Summary

### Security

The rule underneath everything else: **the key never reaches the client**.
Server-side code keeps it in environment variables or a secrets manager;
browser apps proxy through their own backend (a route handler is enough) so
the key stays on the server. Apply least privilege by issuing one key per
environment and per integration — a staging key can't touch production, and a
leaked reporting key can't write. Wherever keys are accepted, validate
responses before trusting them: an unexpected `401` on a previously-working
call is a signal (revocation, rotation, or compromise), not just a retry.

### User Experience

Authentication failures are the moment users decide whether your integration
is trustworthy. Catch auth errors and translate them into plain language —
"Your connection to storage expired, please reconnect" beats
`Error: INVALID_API_KEY`. Never loop users through silent retries on a `401`;
surface a single clear action (re-authenticate, contact an admin). When the
integration runs unattended, implement automatic rotation *before* expiry:
create the new key, deploy it, verify, then revoke the old — the
[rotation workflow](#key-rotation) applies here. Supporting both interactive
and programmatic auth paths is fine, but each should have one obvious,
documented way in.

### Development

Environment-specific configuration isn't optional: production, staging, and
development should each have their own key **and** base URL, wired through a
single config module so a staging client can never point at production by
accident. Cover the auth boundary in tests — the valid-key, invalid-key, and
expired-key cases above are the minimum set, and they run without touching
production data. Log authentication failures (with code, never with the key
itself) and alert on spikes: a burst of `401`s is either a deploy gone wrong
or someone probing. Finally, document your own auth flow — which key goes
where, how rotation happens, who owns it — in the same runbook as the
integration itself.
