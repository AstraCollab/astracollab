## API Key Authentication

All AstraCollab API endpoints require authentication using API keys. You can manage your API keys through the dashboard or via the API.

## Getting Your API Key

1. **Dashboard**: Navigate to your organization settings in the AstraCollab dashboard
2. **API Keys Section**: Go to the API Keys tab
3. **Create Key**: Click "Create API Key" and give it a descriptive name
4. **Copy Key**: Copy the generated API key (it starts with `ak_`)

<Warning>
  API keys are only shown once when created. Make sure to copy and store them securely.
</Warning>

## Using Your API Key

Include your API key in the `Authorization` header of all API requests:

```bash
Authorization: Bearer your-api-key-here
```

### Example Request

```bash
curl -X GET "https://api.astracollab.app/v1/files" \
  -H "Authorization: Bearer ak_1234567890abcdef"
```

## API Key Permissions

API keys inherit the permissions of the organization they belong to:

- **Read Access**: View files, folders, and metadata
- **Write Access**: Upload, update, and delete files
- **Admin Access**: Manage API keys, billing, and organization settings

## Security Best Practices

<Note>
  Keep your API keys secure and never expose them in client-side code.
</Note>

### Key storage

Store keys where only your server can reach them — environment variables are
the baseline, a secrets manager (AWS Secrets Manager, Doppler, Vault) is the
upgrade. A key in environment variables survives deploys without living in
code; a key in source code survives in git history forever, which is why
"never commit keys" is a *pre-commit* rule: add `.env` to `.gitignore` before
the first commit, not after the first leak. For browser applications, the key
belongs behind your own backend — a route handler that proxies to AstraCollab
— because anything shipped to the browser is public.

### Key isolation

Use one key per environment (dev, staging, production) and, ideally, one per
application or service. Environment isolation means a staging incident can
never touch production data; application isolation means revoking a
compromised integration's key doesn't take down unrelated systems. When
multiple apps share a key, you can't rotate one without breaking the rest —
and you can't tell from usage logs which app made which request. If a key
must cross environments temporarily, plan the rotation before the temporary
becomes permanent.

### Key rotation

Rotate on a schedule (quarterly works for most teams) rather than waiting for
a reason. The safe sequence: create the replacement key, deploy it to all
consumers, verify traffic is flowing on the new key via usage logs, then
revoke the old one. Revoke-then-create is how outages happen. After any
suspected compromise, skip the schedule and rotate immediately — a rotation
costs minutes; an intruder with your key costs more.

### Least privilege

Issue keys scoped to the operations they actually perform. A read-only
reporting job doesn't need delete access; an upload worker doesn't need key
management. Narrow scope is what makes every other practice more effective:
the leaked key that can only read is an inconvenience, not a breach. When
your integration's needs grow, grow the key's scope deliberately — in a
change you reviewed — rather than minting every new key as an admin.

## Rate Limiting

API keys are subject to rate limiting based on your plan:

- **Free Plan**: 1,000 requests per hour
- **Creator Plan**: 10,000 requests per hour
- **Studio Plan**: 50,000 requests per hour
- **Production Plan**: 100,000 requests per hour

Rate limit headers are included in all responses:

```
X-RateLimit-Limit: 1000
X-RateLimit-Remaining: 999
X-RateLimit-Reset: 1640995200
```

## Error Responses

### Invalid API Key

```json
{
  "success": false,
  "error": {
    "code": "INVALID_API_KEY",
    "message": "Invalid or expired API key",
    "details": {
      "keyId": "ak_1234567890abcdef"
    }
  }
}
```

### Rate Limited

```json
{
  "success": false,
  "error": {
    "code": "RATE_LIMITED",
    "message": "Rate limit exceeded",
    "details": {
      "limit": 1000,
      "reset": 1640995200
    }
  }
}
```

## Managing API Keys

You can manage your API keys through the API:

- `GET /keys` - List all API keys
- `POST /keys` - Create a new API key
- `DELETE /keys/{keyId}` - Revoke an API key

See the [API Keys](/api-reference/keys/create) section for detailed endpoint documentation.
